# Re.Pack + Module Federation v2 — setup

Generated by `/repack-init`. This wires a **host** app that loads a **remote**
(mini-app) chunk on demand.

## 1. Dependencies

```bash
# Core Re.Pack + Rspack
pnpm add -D @callstack/repack @rspack/core
# Shared singletons used by the example configs (match your RN version)
pnpm add @react-navigation/native @react-navigation/native-stack \
         react-native-safe-area-context react-native-screens
```

Re.Pack replaces Metro — make sure your `react-native.config.js` points the
bundler commands at Re.Pack and that no `metro.config.js` is in effect.

## 2. Files

- `rspack.config.host.mjs` → host build config (rename to `rspack.config.mjs` in the host).
- `rspack.config.remote.mjs` → remote build config (one per remote).
- `ScriptManager.setup.js` → runtime resolver the host imports **before** rendering, so federated chunks resolve at runtime.

Replace the placeholders: `[HOST_NAME]`, `[REMOTE_NAME]`, `[REMOTE_PORT]`.

## 3. Shared singletons (critical)

`react` and `react-native` (and navigation libs) are declared `singleton: true`
in **both** host and remote. The **host** sets `eager: true` (loads them with the
host bundle); each **remote** sets `eager: false` (reuses the host's copy). Keep
the version lists identical across host and all remotes — a mismatch ships two
copies of React and crashes at mount.

## 4. Run

```bash
# Terminal 1 — remote dev server (must match [REMOTE_PORT])
pnpm react-native start --config rspack.config.remote.mjs --port [REMOTE_PORT]
# Terminal 2 — host
pnpm react-native start --config rspack.config.mjs
```

## 5. Production hosting

Build each remote and upload its `mf-manifest.json` + chunks to a CDN. Point the
host's `remotes` map at the CDN URL instead of `localhost` (env-aware). Always
keep a fallback for when a remote fails to download — see
`memory-bank/standards/system-architecture.md`.
